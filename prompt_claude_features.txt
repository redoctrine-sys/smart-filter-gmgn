Tugas: Implementasi 2 fitur baru secara berurutan, dengan arsitektur Hermes Agent + AutoResearch.
Project: smart-filter-gmgn

## Konteks Arsitektur

Saat ini sistem menggunakan pipeline polling + FilterEngine deterministik (YAML template → hard_rules/scoring/boosters → static score). 
Kita akan MENAMBAHKAN layer agentic di atas existing pipeline, BUKAN mengganti. Pipeline tetap jalan sebagai pre-filter, lalu Hermes Agent layer melakukan reasoning + research sebelum alert dikirim.

Flow baru:
  Pipeline (existing) → Token lolos filter → HermesAgent.analyze(token) → AutoResearch → Category Insight + Entry/Risk Plan → Enhanced Alert ke Telegram

### Step 4: Buat Hermes Agent dengan AutoResearch (src/hermes/agent.ts) [NEW]
Ini adalah layer agentic baru. Gunakan pattern yang sama dengan src/narrative/gemini.ts (Gemini API).

1. Buat HermesAgent class:
   - Input: TokenSnapshot + FilterDecision + CategoryBreakdown
   - Method: analyze(token, decision) → HermesAnalysis

2. AutoResearch prompt ke Gemini:
   - Berikan semua data metrik token yang sudah ada
   - Berikan category breakdown dan insight
   - Minta Gemini untuk:
     a) Validasi apakah category insight masuk akal
     b) Berikan risk assessment (1-10)
     c) Generate entry plan: area buy, DCA levels.
        ATURAN SIZING WAJIB: Max 0.1 SOL per buy. Max total position 0.5 SOL (5 entries max).
        Volume dan Market Cap menentukan agresivitas DCA:
        - Aggressive: DCA di -10%, trigger jika vol > $2K. Max 5 entries.
        - Moderate: DCA di -15%, trigger jika vol > $5K + TA confirm. Max 4 entries.
        - Safe: DCA di -25%, trigger jika vol spike > 3x + TA confirm. Max 2 entries.
     d) Generate risk plan: stop loss level, take profit targets (2x, 5x, 10x), position sizing suggestion
     e) Generate conviction level: LOW / MEDIUM / HIGH / VERY HIGH

3. Output interface HermesAnalysis:
   - categoryInsight: string
   - riskAssessment: number (1-10)
   - conviction: "LOW" | "MEDIUM" | "HIGH" | "VERY_HIGH"
   - entryPlan: { zoneLow, zoneHigh, dcaLevels[], maxEntries, entrySizeSol, reasoning }
   - riskPlan: { stopLoss, tp2x, tp5x, tp10x, reasoning }
   - strategyType: "AGGRESSIVE" | "MODERATE" | "SAFE"
   - researchNotes: string (1-2 kalimat insight tambahan dari Gemini)

## Catatan Penting
- JANGAN ubah logic FilterEngine atau template YAML yang sudah ada
- Hermes Agent adalah LAYER TAMBAHAN, bukan pengganti
- Semua fitur baru harus bisa di-toggle via env variable
- Gunakan pattern error handling yang sama dengan narrative/gemini.ts (fallback graceful)
- Entry/Risk plan harus tetap muncul meski Gemini error (gunakan fallback dari data statis)

### Fitur 3: Strategy Optimizer Loop (Feedback Loop) [NEW]
Fitur ini adalah sistem reviewer mingguan per pipeline yang mendeteksi penurunan performa, meng-generate 3 strategy variants, mem-backtest semuanya, dan merekomendasikan variant terbaik berdasarkan performa volume/mcap.

1. Buat `src/hermes/performanceTracker.ts`:
   - Simpan historical weekly stats per pipeline (win rate, PnL, realized SOL, calls).
   - Buat method untuk mendeteksi `decline` minggu-ke-minggu: Trigger jika ROI (avg PnL) turun drastis > 15% minus.

2. Buat `src/hermes/strategyOptimizer.ts`:
   - Dijalankan via weekly cron (setiap Senin 08:00 WIB).
   - Cek `performanceTracker.compare()`. Jika performa stabil, skip (tidak lanjut optimasi).
   - Jika terdeteksi `decline`, mulai fase optimasi:
     a) Analisis metric lift 7 hari terakhir (cari dead weight & hidden gems).
     b) Generate 3 variant YAML template:
        - 🔴 Aggressive: threshold turun, poin TA naik. Evaluasi volume min $2K, DCA lebih sering.
        - 🟡 Moderate: balanced tweak dari data lift. Evaluasi volume min $5K, DCA butuh konfirmasi TA.
        - 🟢 Safe: threshold naik, hapus dead weight metric. Evaluasi volume min $10K, minim DCA.
     c) **Backtest SETIAP variant** terhadap data 7 hari terakhir secara independen. Tweak metric `base_size_sol` dan `dca_aggressiveness` pada simulator exit sesuai tipe strategy.
     d) Bandingkan metrik akhir: win rate, avg PnL, total realized SOL, max drawdown, total calls.
     e) Pilih variant terbaik dan laporkan ke Telegram.

3. Buat `src/hermes/templateMutator.ts`:
   - Helper untuk membaca template `.yaml` saat ini dan mem-parsing output LLM menjadi `.yaml` baru tanpa merusak format aslinya.

4. Update Telegram Commands & Integrasi (`src/telegram/bot.ts`):
   - Command `/optimize <pipeline> <window>`: trigger manual jalankan flow `performanceTracker` -> `strategyOptimizer`.
   - Command `/approve <pipeline>`: apply variant rekomendasi menjadi template aktif (menggantikan YAML lama).
   - Command `/revert <pipeline>`: kembalikan YAML ke versi sebelumnya (rollback).
   - Pastikan output di telegram memunculkan tabel komparasi 3 strategy, menunjukkan expected win rate dan jumlah calls berdasar hasil backtest, lalu mencantumkan status apakah sistem dalam mode `AUTO_APPLY` atau butuh `/approve`.

### Fitur 4: Backtester Entry/Exit Integrity Snapshot [NEW]
Fitur ini bertugas melakukan snapshot otomatis terhadap metrik on-chain (terutama integritas token seperti jumlah top holder, persentase bundler, dev holding, market cap) pada SAAT TEPAT simulasi entry dan exit (TP/SL/Rug) di dalam backtester.

1. Update `src/backtester/types.ts`:
   - Tambahkan tipe `IntegritySnapshot` yang berisi: `timestamp`, `marketCap`, `top10HoldersPct`, `bundlerPct`, `devHoldingPct`, dll.
   - Update `SimulatedCall` atau `ExitSimulationResult` untuk menyimpan `entrySnapshot` dan `exitSnapshot`.

2. Update `src/backtester/exitSim.ts`:
   - Saat backtester mensimulasikan ENTRY (saat token lolos filter), tangkap data `IntegritySnapshot` saat itu.
   - Saat backtester mensimulasikan EXIT (ketika menyentuh TP, SL, atau Rug), tangkap lagi `IntegritySnapshot` pada timestamp exit tersebut.
   - Hal ini memungkinkan kita membandingkan perubahan distribusi token dari titik masuk hingga titik keluar (misalnya: apakah bundler dump selama hold time?).

3. Integrasikan ke Reviewer (`src/backtester/reviewer.ts`):
   - Gunakan data `entrySnapshot` vs `exitSnapshot` ini untuk menganalisa korelasi rug/SL dengan pergerakan wallet top holder atau bundler.
   - Insight dari perbandingan ini dapat diumpankan kembali ke `strategyOptimizer` (misal: "Jika bundler > 20% saat entry, 80% berujung SL karena bundler exit. Rekomendasikan pinalti poin bundler").
